# Release runbook — shipping a spec version (the implementation PR)

The detailed, step-by-step checklist for the **implementation PR** (PR 2 in
`SKILL.md`): the single PR that adds an Accepted RFC's schema fields, bumps the
spec version, flips the RFC to Implemented, and updates + versions the docs.
Everything here lands in **one PR**.

Originally extracted from the v1.3.0 → v1.3.1 (Skills Extension) release and
de-drifted for the current repo layout (RFCs source in `/rfcs/`, docs RFC
index auto-generated by `sync-rfcs.js`, version drift guarded by
`scripts/check-version-consistency.mjs`).

## Inputs

| Input | Example |
|-------|---------|
| `OLD_VERSION` / `NEW_VERSION` | `1.4.0` / `1.5.0` (additive optional field = minor bump) |
| `OLD_VTAG` / `NEW_VTAG` | `v1.4` / `v1.5` (docs archive dir + schema URLs) |
| `RFC_NUMBER` / `RFC_SLUG` / `RFC_TITLE` | `0011` / `workflow-states-as-agents` / `Workflow States as Agents` |
| `FEATURE_SUMMARY` | one-line description |

## Steps

### 1. Flip the RFC to Implemented

**File:** `rfcs/{RFC_NUMBER}-{RFC_SLUG}.md` (the source — **not** the generated
`promptpack-docs/docs/rfcs/` copy). The RFC already exists from the Draft PR;
here set `Status: Implemented`, bump `Updated`, add a Revision History line.
(If shipping design + implementation in one go, author it at `Implemented`.)

### 2. Update the JSON schema

**File:** `schema/promptpack.schema.json` (source of truth)

1. Bump `"version"` `OLD_VERSION` → `NEW_VERSION`.
2. Update the root `"description"` to mention the feature.
3. Add new properties to existing definitions / new `$defs` as needed.
4. **Do NOT** add new entries to any `"required"` array (backward compatibility).
5. Validate JSON: `cat schema/promptpack.schema.json | python3 -m json.tool > /dev/null`.

### 3. Archive the outgoing spec docs

Copy the current spec docs into the archive dir, per `VERSIONING.md`:

```bash
mkdir -p promptpack-docs/docs/spec/{OLD_VTAG}
cp promptpack-docs/docs/spec/*.md promptpack-docs/docs/spec/{OLD_VTAG}/
```

For **each** archived file:
1. Frontmatter — add `title: "... ({OLD_VTAG})"` (keep `sidebar_position`).
2. Version badge — swap the class, not a colour. The rules live in
   `promptpack-docs/src/styles/site.css` (`.ppVersionBadge`,
   `--current`, `--archived`), written in Atlas tokens so both themes follow:
   ```mdx
   <span className="ppVersionBadge ppVersionBadge--current">{OLD_VTAG} · current</span>
   ↓
   <span className="ppVersionBadge ppVersionBadge--archived">{OLD_VTAG} · stable</span>
   ```
   These badges used to be `<div style={{...}}>` blocks with hardcoded
   `#10b981` / `#6b7280` fills, which could not follow the light/dark theme.
   Do **not** reintroduce an inline-styled badge, and do **not** add an emoji —
   the badges used to carry glyphs, removed under the house rule "Emoji: never"
   (see the AltairaLabs voice rules). Badge text is lowercase mono machine data.

   > The Astro migration moved these classes over but left the rules behind, so
   > every spec badge rendered as unstyled text until they were restored. If a
   > badge looks like plain text, check that `site.css` still defines them —
   > this runbook pointed at a Docusaurus path (`src/css/custom.css`) for
   > several releases while nothing defined them at all.
3. Add an archived warning right after the badge:
   ```mdx
   :::caution[Archived Version]
   This is the **{OLD_VTAG}** documentation. For the latest features, see [{NEW_VTAG} docs →](../overview)
   :::
   ```
4. Remove any `:::note[Version Information]` block (a current-version element).

> **Aside syntax is Starlight's, not Docusaurus's.** The only valid types are
> `note`, `tip`, `caution` and `danger` — `info` and `warning` are Docusaurus
> spellings, and an unrecognised type is not an error: the whole block falls
> through as literal `:::` text in the middle of the prose. The title is a
> remark-directive label and must be **bracketed** (`:::note[Title]`); written
> space-separated it is silently dropped. 130 asides across 52 files carried one
> or both of these faults after the migration.

> `schema-reference.md` is auto-generated from the schema (don't hand-write it);
> regenerate and copy the new version into both `docs/spec/` and the archive dir.

### 4. Update the current spec docs to the new version

> The site chrome needs **no** edit here. The standards strip, homepage and
> footer read the version from `schema/promptpack.schema.json` at build time
> (`docusaurus.config.ts` → `customFields.specVersion` → `useSpecVersion()`).
> Never hardcode the current version in a component — `version-check` only
> compares the schema against the README, so it would go stale silently.
> Capability-card pills like `'v1.4'` are the version a feature *landed in* and
> stay hardcoded on purpose.

In `promptpack-docs/docs/spec/`: `overview.md` (badge → `{NEW_VTAG} · current`,
"What's New" info box, feature in the solution snippet), `structure.md`,
`architecture-patterns.md` (layer diagram, compatibility matrix), `examples.md`
(a full example pack), `schema-guide.md` (property tables + feature section).
Skip `schema-reference.md` (regenerated).

### 5. Update `docs/spec/versions.md`

Move the old version to "Previous Versions" (link `./{OLD_VTAG}/overview`), make
`{NEW_VTAG}` current with its feature list, add the support-policy row, a
"Migration from {OLD_VTAG} to {NEW_VTAG}" section, and a Version History row.
`versions.md` is the canonical version index — keep it accurate.

### 6. Register the archive in the sidebar

The nav lives in `promptpack-docs/astro.config.mjs` (Starlight's `sidebar`
array), not in a `sidebars.ts` — that file went with Docusaurus. Add the newly
archived version as the **first entry inside the `Archive` category** (newest
first), using the `archive()` helper at the bottom of the file:

```js
label: 'Archive',
collapsed: true,
items: [
  archive('{OLD_VTAG}'),      // ← newest first
  archive('v1.4.1'),
  /* … older versions … */
],
```

`archive(version, pages?)` defaults to the full seven-page set; pass an explicit
list only for an older version that never had all seven.

The label is the bare version — **no "(Archived)" suffix**; the parent
category already says it. Every archived version lives under `Archive` so the
current spec pages are not outnumbered in the nav.

If you add a how-to guide, register it in the Guides category too.

### 7. Update `README.md` (version-check lockstep)

`scripts/check-version-consistency.mjs` (the `version-check` CI job) **fails the
PR** unless the schema version, the README badge, and the README versioned URL
all match. Update both in README to `NEW_VERSION`:
- the `Spec-vX.Y.Z-blue` shields badge,
- the versioned schema URL `schema/vX.Y.Z/promptpack.schema.json`.

Also add the feature to the "What's in a pack" / "Key Features" lists and an
example section.

### 8. Sync the static schema (`latest` + versioned)

```bash
npm --prefix promptpack-docs run sync-schema
```
Copies `schema/promptpack.schema.json` → `static/schema/v{NEW_VERSION}/` and
`static/schema/latest/`. (Also runs automatically in the docs `prebuild`.) The
**authoritative public publish** happens when you push the `v{NEW_VERSION}` git
tag after merge → `publish-schema.yml` writes those files and commits to `main`.
Never hand-edit `static/schema/**`.

### 9. Update the RFC index

- **`rfcs/README.md`** (hand-maintained) — move the RFC's row to the Implemented table.
- **`promptpack-docs/scripts/sync-rfcs.js`** — add `{RFC_NUMBER}: '{NEW_VTAG}'` to
  the `RFC_SPEC_VERSION` map.
- **Do NOT** hand-edit `promptpack-docs/docs/rfcs/index.md` — its table/counts are
  auto-generated by `sync-rfcs.js`.

### 10. How-to guide (if the feature warrants one)

Add `promptpack-docs/docs/guides/{name}.md` following an existing guide
(`add-workflow.md`, `setup-agents.md`), and register it in the Guides
category in `astro.config.mjs`.

## Verification

```bash
cat schema/promptpack.schema.json | python3 -m json.tool > /dev/null   # valid JSON
node scripts/check-version-consistency.mjs                              # version lockstep
npm --prefix promptpack-docs run build                                  # links + MDX + SSR
```
Spot-check locally (`npm --prefix promptpack-docs run dev`, or `preview`
after a build — there is no `serve` script; that was Docusaurus): `/docs/spec/overview`
(current badge), `/docs/spec/{OLD_VTAG}/overview` (archived badge + warning),
`/docs/spec/versions`, `/docs/rfcs/{RFC_SLUG}`.

## Notes

- `schema-reference.md` uses generated `<a name="...">` anchors the site cannot
  resolve; the resulting link warnings are expected. (`onBrokenAnchors` was a
  Docusaurus option and no longer exists in `astro.config.mjs`.)
- All new schema properties must be optional (never in `required`) to stay
  backward compatible within a major version.
- After merge, tag the release `v{NEW_VERSION}` to trigger the schema publish.
